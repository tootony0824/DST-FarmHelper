# 农事手册 (Farm Helper)

Don't Starve Together 的种地信息面板。**纯客户端显示 mod**，不修改任何游戏数据，
联机时只有你自己需要装。

## 怎么启用

1. **完全退出 DST**（包括后台进程，否则读不到新文件夹）
2. 启动游戏 → 主菜单左侧 **「模组」**
3. 切到 **「本地模组」** 标签页，找到 **农事手册**
4. 点 **启用**，然后进入世界
5. 按 **H** 打开 / 关闭面板

想换快捷键或让面板进游戏就自动展开：在模组列表里点「农事手册」右侧的
**配置**（齿轮图标）即可，不用改代码。

## 面板里能看到什么

| 位置 | 内容 |
| --- | --- |
| 顶部 | 当前季节 + 还剩几天 |
| 顶部第二行 | **本季配比** —— 当前季节按什么比例种能自平衡（详见下面一节） |
| 表格第 1 列 | **作物名**（长出来的东西） |
| 表格第 2 列 | **种子名**（背包里看到的那个） |
| 表格第 3~5 列 | 该作物的养分**净变化**：`-` 是吃掉的，`+` 是产出的 |
| 最后一列 | 适宜季节，**当前季节的那个字会变绿** |
| 底部 | 养分循环规则 + 一个现成的平衡配比 |

表格按「主要消耗哪种养分」分成三组排列，方便和底部的配比说明对照。

### 养分那三列怎么读

一粒种子种下去，它**不只是消耗**——每长一个阶段，吃掉某些养分的同时，
会把**等量的养分还给「它不吃」的另外那几种**。所以一格里有正有负才是完整的一笔账：

```
胡萝卜    -4    +2    +2
          │     └─────┴── 产出：2 点堆肥 + 2 点粪肥
          └───────────── 消耗：4 点催长剂
```

读作：**每长一个阶段，吃掉 4 点催长剂，同时产出 2 点堆肥和 2 点粪肥。**

| 作物 | 催长剂 | 堆肥 | 粪肥 | |
| --- | --- | --- | --- | --- |
| 胡萝卜 / 南瓜 | **-4** | +2 | +2 | 低消耗档 |
| 洋葱 / 石榴 | **-8** | +4 | +4 | 高消耗档 |
| 玉米 / 芦笋 | +2 | **-4** | +2 | |
| 大蒜 / 榴莲 | +4 | **-8** | +4 | |
| 土豆 / 茄子 | +2 | +2 | **-4** | |
| 火龙果 / 辣椒 | +4 | +4 | **-8** | |
| 番茄 | -2 | -2 | +4 | 混合型（同时吃两种） |
| 西瓜 | +4 | -2 | -2 | 混合型 |

**每一行三个数加起来都是 0** —— 它只是把养分从一种换成了另一种，总量没变。
这就是「配比」能成立的根据。

顺带一提：**净消耗的量 = 它需要的量**。胡萝卜的催长剂列写 `-4`，
就是种它需要 4 点催长剂（低消耗档），洋葱写 `-8` 就是高消耗档。

名称两列都是**直接读游戏自己的本地化字符串**（`STRINGS.NAMES`），不是硬编码的。
所以你切英文 / 繁体，面板会跟着变；游戏改译名也不用改代码。

## 两个页面

面板分两页。**切页用键盘**（比点按钮可靠）：

| 按键 | 作用 |
| --- | --- |
| **H** | 打开 / 收起面板（默认停在「信息」页） |
| **J** | 在「信息」和「种植」两页之间切换 |

**面板收着的时候按 J，会直接打开面板并停在「种植」页** —— 也就是说
「按 J 就到第二页」，连按两下就在两页之间来回。

两个键都能在游戏的**模组设置**里改。注意**不要把它们设成同一个键** ——
mod 会检测到并把切页键跳过（日志里会写一行说明）。

标题栏右上角的 **[信息] [种植]** 按钮也还在，点击同样能切页；
当前所在的那一页底色会亮一些。

### 第一页：信息

- 当前季节 + 剩余天数
- 本季配比（按季节算出来的种植搭配）
- **两张种植布局图**：一块地（3×3）和两块地叠起来（18 格）
- 14 种作物的「作物名 / 种子名」对照、养分**净变化**、适宜季节
- 底部是养分循环的规则说明

### 第二页：按你手里的种子算

这一页是给你**自己安排**用的：

1. **调数量** —— 每种作物右边有 `−` 和 `+` 两个按钮，点一下加减 1。
   把你手里有的种子各有多少个设进去。
2. **选地皮形状** —— `3×3` 或 `3×3 ×2`。
3. **看示意图** —— 下面会画出每个格子摆什么，**用颜色区分作物**，
   旁边是「颜色 → 作物名」的图例。

**数量的比例决定格子怎么分。** 比如你设「胡萝卜 5、玉米 4、土豆 3」，
选 3×3 时会按 4 : 3 : 2 铺进 9 个格子（除不尽的按比例补足）。

番茄和西瓜不参与排布 —— 它们同时吃两种养分，方向不唯一（和第一页的理由一样）。

> 按钮交给游戏自己的控件系统处理（`TEMPLATES.InvisibleButton`），
> 按下时触发一次，按住不放不会连续加。
> 拖面板要抓标题栏的空白处（压在按钮上不会触发拖拽）。

## 本季配比：这个季节该种什么

面板标题下面那行「本季配比」会**跟着季节自动变**。它是这么算出来的。

**先看结论**（这就是面板会显示的内容）：

| 季节 | 本季配比 | 净收支 |
| --- | --- | --- |
| 春 | 胡萝卜 1 株 : 玉米 1 株 : 土豆 1 株 | 三项全部归零 |
| 夏 | 洋葱 1 株 : 大蒜 1 株 : 火龙果 1 株 | 三项全部归零 |
| 秋 | 胡萝卜 1 株 : 玉米 1 株 : 土豆 1 株 | 三项全部归零 |
| 冬 | 胡萝卜 1 株 : 芦笋 1 株 : 土豆 1 株 | 三项全部归零 |

四个季节都能凑出 **1 : 1 : 1**，不用施肥。数字是**株数**，不是份数。

**这份结果和中文社区手工试出来的组合吻合。** 网上流传的一套 1:1:1 间种搭配是：

- 春秋：胡萝卜 : 玉米 : 茄子
- 春夏：火龙果 : 洋葱 : 大蒜
- 夏季：辣椒 : 石榴 : 大蒜
- 冬季：土豆 : 芦笋 : 胡萝卜

把养分收支完全相同的作物代进去（茄子 ≡ 土豆、南瓜 ≡ 胡萝卜、辣椒 ≡ 火龙果、
石榴 ≡ 洋葱 —— 这几对的消耗/归还点数一模一样），和上表逐条对得上。
一边是算出来的，一边是手工试错试出来的，能对上说明机制没理解偏。

**为什么是这么配的：**

1. 一株作物吃掉的养分，会**原封不动地还给它不吃的那几种**（详见下一节）。
   所以每一株的净变化，三项加起来永远是 0 —— 它只是把养分**换了种类**。
2. 于是唯一要做的事就是让「被吃掉的总量」在三种养分上打平。
3. 但不同季节能种的作物不一样。比如夏天没有低消耗档（4 点）的催长剂作物，
   只有洋葱和石榴（都是 8 点），那就得让另外两组也凑到 8 点，比例才配平。

**所以面板不是给一张写死的表，而是每次季节变了就重新算一遍。**
算法就在 `modmain.lua` 的「四、当前季节的平衡配比」一节里：

```
把本季能种的作物按「它主要吃哪一种养分」分成三组
  → 每组只能凑出自己「消耗档位最大公约数」的倍数
  → 三组取最小公倍数，就是能配平的最小规模
  → 每组用完全背包凑出这个规模，株数最少的那组解就是推荐配比
```

游戏以后改了作物消耗档位，这边会**自动跟着变**，不用改代码。

**番茄和西瓜不参与配比。** 这两种是**混合消耗型**：番茄同时吃催长剂和堆肥
（2 + 2），西瓜同时吃堆肥和粪肥（2 + 2）。它们的方向不是单一的，
放进配比里会让「几株」这个问题变得没有唯一答案，所以面板只统计
「一次只吃一种」的作物。这两种单独种在别的地块上就好。

## 种植布局：一块地皮怎么摆

> ★ **v2.6.0 重写。** 这一节以前写的是「3×3 无解 / 2×2 不够 / 只有中列能巨大」——
> 那是把**养分账本的单位（格）**当成了种法。照它种下去，株距恰好等于家族判定
> 半径 4，一张巨大作物都出不来。正确结论就在下面。
>
> 面板右上角那张图就是答案：**一个方框 = 一块地皮**，里面按配比挤成一堆。

### 单位先对齐（之前就栽在这里）

玩家说的「一块地皮」= 游戏里的**一个 tile** = 4×4 世界单位（`TILE_SCALE = 4`）。
一台耕地机开 2×2 = **4 块地皮**；一块地皮上按 `FARM_TILL_SPACING = 1.25` 的间距
最多能锄 16 个土堆，但**同一 tile 超过 10 株要吃「过度拥挤」压力**
→ 常见是 9 株，最优是 10 株。

（旧版把 wiki 的「每块田地 9 格」读成了「9 个 tile 各一株」，于是绕出了
那一串错误结论。它其实是「一块地皮里锄 9 个土堆」。）

### 三条规则

| 规则 | 数值 | 要点 |
| --- | --- | --- |
| 家族 | 半径 1 tile 内同种 ≥4 株（含自己） | **可以跨地皮凑** |
| 养分 | **按 tile 记账** | **每块地皮内**的比例就要零和 |
| 拥挤 | 同一 tile ≤10 株 | 9~10 株最合适 |

「养分按 tile 记账」这条是英文 wiki 说死的：

> Nutrients are calculated per-tile, not in a radius around each plant — so be
> mindful to have the right proportion of plants in each tile, while also
> connecting the plants to their families in other tiles.

### 为什么必须「挤成一堆」

家族判定半径是 4 世界单位，**恰好等于一块地皮的边长**。
按「一格一株」铺开种时，相邻那株不偏不倚落在圆周上（临界），
斜角 4×√2 ≈ 5.7 直接出界 —— 半径 4 的圆里只剩它自己。
逐株模拟的结果（`_family.py`）：

| 排法 | 株距 | 家族通过 |
| --- | --- | --- |
| 2×2 同种 | 4（按格铺） | **0/4** |
| 一行 4 株 | 4 | 0/4 |
| 3×3 全同种 | 4 | 5/9（四角永远挂） |
| 2×2 同种 | **1.25（挨着锄）** | **4/4** |

玩家实测还有一条：**4 个同种排成一排时，第 4 株落在判定边界上，可能失效**
→ 排 2×2 比排一条线稳。

### 四季配比（面板自动算，这里是它的离线核对）

| 季 | 每块地皮 | 家族 |
| --- | --- | --- |
| 秋 | 5 番茄 + 5 土豆（10 株） | 单块自足 |
| 春 | 5 番茄 + 5 土豆（10 株） | 单块自足 |
| 夏 | 6 番茄 + 3 火龙果（9 株） | 要 2 块拼，火龙果靠边界 |
| 冬 | 3 南瓜 + 3 芦笋 + 3 土豆（9 株） | 要 2 块拼，少的那种靠边界 |

「要 2 块拼」的意思是：某种作物在一块地皮里凑不满 4 株，就把它**都挪到地皮
边界**上，跟隔壁那块地皮的同种挨在一起 —— 家族的搜索不分地皮，跨过去照样算数。
（夏季那组和日文攻略 note.com 的说法一字不差。）

<details>
<summary>以下为 v2.5.2 及更早的旧推导，结论已被上面推翻，留档备查</summary>

### 先说两个反常识的事实：要 4 株，而且「相邻」只有上下左右

游戏的判定在这几个常量里（`tuning.lua:5797-5800`、`constants.lua`）：

```lua
FARM_PLANT_SAME_FAMILY_MIN        = 4    -- 同种 ≥4 株（注释：includes the plant doing the test）
FARM_PLANT_SAME_FAMILY_RADIUS     = 4    -- 半径 4 的圆形搜索
FARM_PANT_OVERCROWDING_MAX_PLANTS = 10   -- 同一块地皮超过 10 株才吃「过度拥挤」
TILE_SCALE                        = 4    -- ★ 一格地皮的中心距正好是 4 个世界单位
```

`farm_plants.lua:178-182` 的实际判定是**数半径 4 以内有多少株同种**：

```lua
local num_plants = #TheSim:FindEntities(x, y, z, inst.plant_def.family_check_dist, {tag}, NOT_TAGS)
return num_plants < inst.plant_def.family_min_count
```

**关键在几何**（v2.2.0 才算对的账，v2.2.2 补充耕地落点细节）：

- 相邻两格的**格心距** = `TILE_SCALE` = **4**，正好等于搜索半径 → 按格心种时，
  **上下左右 4 个正交邻格**算数，斜对角（4×√2 ≈ 5.7 > 4）不算；
- 所以每株要凑的是「**自己 + 3 个同种正交邻居**」，光「总数 ≥4」没用，摆得散照样全灭。

★★ **但注意：耕地不是摆在格子正中，而是摆在锄头落点**（`farmtiller.lua:15`
`SetPosition(pt:Get())`，一格地皮只放一块）。所以上面的「正交才算」是
**按格心下锄**时的理想化结论，真实规则是纯距离：

- 都点格子中间 → 正交 ✓、斜角 ✗（和网格模型一致）；
- 贴着格边点 → 相邻格两株最远能到约 8（**不算了**），斜角两株最近能贴到近 0（**算**）。

**实践结论：想稳就点格子中间下锄**，让耕地落在格心附近，
上面的网格模型（含面板第二页的逐株判定）就完全成立；
故意贴边种可以把斜角也拉进家族，但那是精细化操作。

**三个后果**：

1. **3 株不够，要 4 株。**
2. **2×2 方块不够！** 2×2 里每株（按格心）只有 2 个正交邻居 + 自己 = 3 < 4 ——
   之前 README 写「排成 2×2 最稳」是**错的**（当时没算 TILE_SCALE）。
   （贴边点锄勉强能救，但别指望。）
3. **矩形地的四个角永远吃家族压力** —— 角上最多只有 2 个邻格。
   想让角上也巨大，只能在角外补种同种作物。

### 于是单块 3×3 无解

| 方案 | 总株数 | 结果 |
| --- | --- | --- |
| 三种各 3 株 | 9 | 养分 ✓，家族 ✗（谁都凑不齐 3 个同种邻居） |
| 三种各 4 株 | 12 | 塞不进 9 格 |

**这两个条件在一块 3×3 里没法同时成立。**

### 那两张图分别是什么

**左边：一块地（3×3）** —— 每种 3 株

```
胡萝卜 胡萝卜 胡萝卜
玉米   玉米   玉米
土豆   土豆   土豆
```

养分收支归零，但**没有一株**能凑齐 3 个同种邻居 → 全部出不了巨大
（收成和养分循环本身是正常的）。

## 养分循环是怎么回事

这块是理解农场的关键，游戏里没直说：

> 作物每进入下一个生长阶段，会**扣掉**标出的养分点数，
> 再把**同样多**的养分平均还给「它不消耗」的那几种。

原文就在这两行（`scripts.zip` 里）：

```lua
-- prefabs/farm_plant_defs.lua:127-130
-- 「归还」的项，正好就是「不消耗」的项
data.nutrient_restoration = {}
for i = 1, #data.nutrient_consumption do
    data.nutrient_restoration[i] = data.nutrient_consumption[i] == 0 or nil
end

-- components/farming_manager.lua:412-428
-- 归还总量 = 实际消耗总量，平均分给要归还的那几项
total_restore_count = total_restore_count + consumptioncount
local nutrient_restore_count = math.floor(total_restore_count / nutrients_to_restore_count)
```

也就是说**总量守恒，只是种类被换掉了**。举个具体的：

| 作物 | 催长剂 | 堆肥 | 粪肥 |
| --- | --- | --- | --- |
| 胡萝卜 | −4 | +2 | +2 |
| 玉米 | +2 | −4 | +2 |
| 土豆 | +2 | +2 | −4 |
| **三种各 1 株** | **0** | **0** | **0** |

所以一块地**只种一种作物，迟早会把某一项掏空**，然后作物开始缺肥生长受阻。

两个相关的数值，游戏里同样没写出来：

- 土壤每项养分的**上限是 100**
- 一块新翻的耕地，三项初始各随机 **20 ~ 40**

**配比原则**：把三列的消耗点数配平就行。上面那个例子就是
`胡萝卜 : 玉米 : 土豆 = 1 : 1 : 1`，可以一直不施肥。

### ★ 养分按「格」结算 —— 配平的真正含义（v2.4.4 补，v2.5.0 修正）

实机测试发现：照着面板的 6/6/6 配平方案种，还是会缺肥。原因在结算粒度：

**养分的消耗和归还都发生在作物自己那一格的土壤上**（`farming_manager.lua:400-455`，
账本是世界 tile 级的，每格三轴各自 0~100，开垦时各随机 20~40）。

所以 6/6/6 的"收支归零"是 **18 格总和**：全图没有净亏损，但**每一格单看都在单向漂移** ——
胡萝卜格每阶段催长剂 -4、堆粪各 +2，催长剂一路见底、堆粪一路涨；
茄子格的粪同理。归还全进自己格子，帮不到旁边吃同一轴的邻居。

数字账：胡萝卜格一季吃 16 点催长剂，初始存量 20~40 —— **第一茬勉强够，
第二茬起中途枯竭**（消耗被钳、记养分压力），这就是"照配平种也缺肥"的来源。

#### 关键更正：总量守恒 —— 缺的不是「量」，是「分布」

`CycleNutrientsAtPoint()` 里扣多少就还多少：

```lua
consumptioncount = math.min(nutrients[n_type], count)   -- 有多少扣多少
total_restore_count = total_restore_count + consumptioncount
```

扣的量 = 还的量，所以**三轴之和永远不变**：每茬净变化三项之和恒为 0，
作物只搬运养分，不生产也不消灭。离线模拟连种番茄 8 茬，30/30/30 → 0/0/90，
合计始终是 90。

那"缺肥"到底是什么？是**某一根轴被抽干**：

- 那一茬会 `depleted` → 记一次养分压力 → 出不了巨大作物；
- 之后凡是要吃这根轴的作物，在这一格都长不好 —— 表现出来就是"缺肥"。

唯一真正流失养分的地方在 `AddTileNutrients()`：`math.clamp(_n + nutrient, 0, 100)`，
归还把某根轴顶过 100 时，超出的部分被直接丢掉。
**扣不够反而不流失**（扣得少、还得也少，两边抵消）。

#### 所以轮作能自愈，而且不用施肥

既然总量守恒，把堆在粪肥上的养分搬回来，只需要"种一茬吃粪肥的作物"。
模拟：番茄连种 4 茬 → 0/0/90，接着种土豆 → 8/8/74 → 16/16/58 …… 自己就养回来了。

**面板第三页「轮作」就是干这个的**：勾上你想种的作物，它枚举所有
**净变化加起来为 0** 的作物链（长度 2~3 茬），按"全当季 > 茬数少 > 水位高"排好给你。
每格照链上的顺序换茬，走完一轮账本回到原点，可以无限循环。

配平器（第二页）的价值因此要讲准：它保证**这一茬全图没有净亏损**（不用大把买肥料），
并把缺口如实报给你；格级漂移要靠第三页的轮作解决。

### ★「一块地皮」和「一格」到底是什么关系（v2.5.2 源码考证）

有玩家反驳得很在理：**"作物是在一块地皮里流通肥料的吧，怎么会是按哪一个种植格子算？"**
直觉上确实是——锄头刨出来的一整块地，看着是一片连续的土。
但源码里那本账**根本不是按地皮开的**，而是按**世界瓦片网格**开的。逐条列证据：

**① 账本是一张覆盖全地图的表，一格一个格子**

`farming_manager.lua` 的 `InitializeDataGrids()`：

```lua
local w, h = _map:GetSize()
_nutrientgrid = DataGrid(w, h)
_moisturegrid = DataGrid(w, h)
_drinkersgrid = DataGrid(w, h)
_overlaygrid  = DataGrid(w, h)
```

`_map:GetSize()` 返回的是**世界瓦片数**（`tilemanager.lua` / `map.lua` 里维护的 w×h）。
也就是说这本账**在你锄地之前就已经存在于整张地图上**了 —— 每一格世界瓦片一个抽屉，
不是"锄出来的那片形状"一个抽屉。世界瓦片边长 `TILE_SCALE = 4`（`constants.lua`），
比一格种植格（`farm_soil`）大得多。

**② 结算时把作物坐标换算成瓦片，只读写那一格**

`CycleNutrientsAtPoint(_x, _y, _z, consume, restore, test_only)`（同文件 400-455）：

```lua
local x, y, z = TheWorld.Map:GetTileCoordsAtPoint(_x, _y, _z)
-- 之后全程 GetDataAtPoint(x, y) / SetDataAtPoint(x, y, ...)
```

作物长得再大、占的土块再宽，进这个函数一律先塌缩成**它脚下**那一个瓦片坐标。
`GetTileNutrients(x, y)` / `SetTileNutrients(x, y, ...)` / `AddTileNutrients(x, y, ...)`
三个接口的签名直接把粒度写在名字里了。

**③ 一块"地皮"其实是若干块独立的土块，每块各占一格**

`farm_plow.lua` 里锄头开挖时是这样长土的（`dirt_anim`）：

```lua
if TheWorld.Map:CanTillSoilAtPoint(_x, 0, _z, true) then
    local soil = SpawnPrefab("farm_soil")
```

而 `CanTillSoilAtPoint`（`components/map.lua`）除了要求地面能种，还有一条
`IsDeployPointClear(..., GetFarmTillSpacing(), ...)`
—— `GetFarmTillSpacing()` 返回 `TUNING.FARM_TILL_SPACING = 1.25`
（`gamemodes.lua` → `tuning.lua`，只有 1/3.2 格瓦片那么宽）。

所以锄头画出来的一片土，是**一堆各自隔开 ≥1.25 的 `farm_soil` 小块**拼出来的，
而不是一整块。每块 `farm_soil` 都落在**自己的瓦片上**（`farm_soil.lua` 里
`SetDeploySmartRadius(0.5) --match visuals`，注释也写了它只管视觉，种子用 CUSTOM spacing）。

**④ 你眼睛看到的"这块土肥/瘦"，是每块土各自的覆盖层**

施肥时（`standardcomponents.lua` 的 `fertilizer_ondeploy`）：

```lua
local tile_x, tile_z = TheWorld.Map:GetTileCoordsAtPoint(pt:Get())
...AddTileNutrients(tile_x, tile_z, ...)
```

也是一格一格加。开垦时 `OnTerraform` 把该格三轴设成随机 20~40，并在
`GetTileCenterPoint(x, y)` 位置放一个 `nutrients_overlay` 实体 ——
**玩家看到的那块土变色，就是这个实体在替它那一格瓦片显示账面。**

**结论：** 地皮是"视觉上连续的土块集合"，账本是"每块土脚下那一格瓦片"。
两者不是一回事——**一块 3×3 的地皮，账面上就是 9 本独立的账**，
土块挨得再近也不串账。这正是配平器（只算总面积总和）救不了单格枯竭的根因，
也是第三页轮作按"同一格换茬"来排的原因。

> 顺带一提，**同一个方向的"半径类"判定是另一套粒度**：
> 家族压力是 `FindEntities(x, y, z, 4, ...)`，半径 4 = 恰好一格瓦片，
> 只数上下左右的正交邻居（斜角 5.7 够不到），要"自己 + 3 个同种"（`farm_plants.lua:178-182`
> + `tuning.lua` 的 `FARM_PLANT_SAME_FAMILY_MIN/RADIUS`）；拥挤度则是
> `GetEntitiesOnTileAtPoint` + 上限 10（同一格内）。所以"格子"在这套系统里
> 反而是**最常被用来当判定单位**的那个概念，唯独养分账本要额外记住它是地图级的。

### 缺啥补啥：三种养分的补给难度完全不是一个量级（v2.2.2 补）

数值直接来自 `tuning.lua` 的肥料养分表（顺序 = {催长剂, 堆肥, 粪肥}）：

| 肥料物品 | 催长剂 | 堆肥 | 粪肥 | 获取 |
| --- | --- | --- | --- | --- |
| 粪便 | 0 | 0 | 8 | ★ 牛群捡屎，量大管饱 |
| 化肥袋 / 蝙蝠粪 | 0 | 0 | 16 | ★★ |
| 腐烂物 | 0 | 8 | 0 | ★ 食物放坏就是，无限 |
| 臭鸡蛋 | 0 | 16 | 0 | ★★ 鸟笼里的蛋放坏 |
| 堆肥 | 0 | 24 | 0 | ★★ |
| **腐烂的鱼** | **16** | 0 | 0 | ★★★ 得钓鱼 |
| 催长剂瓶（合成） | 8 / 16 / 32 | 0 | 0 | ★★★ 要配方慢慢酿 |
| 格罗姆粘液 | 8 | 8 | 8 | ★★ |
| 堆肥包裹 | 24 | 32 | 24 | ★★ 6 腐烂物合成，三样全补 |

**结论：堆肥和粪肥都是「垃圾再生」（食物放坏、牛群拉屎），几乎不要钱；
催长剂只能靠腐烂的鱼或合成瓶，是真正的稀缺资源。**

#### 施用规则：一个物品喂一块地（v2.2.4 核）

施肥物品全部是 **deployable**（部署到地面），`standardcomponents.lua:1797-1802`：

```lua
local function fertilizer_ondeploy(inst, pt, deployer)
    local tile_x, tile_z = TheWorld.Map:GetTileCoordsAtPoint(pt:Get())
    local nutrients = inst.components.fertilizer.nutrients
    TheWorld.components.farming_manager:AddTileNutrients(tile_x, tile_z,
        nutrients[1], nutrients[2], nutrients[3])
```

三条硬规则：

1. **一物一格**：表里的数值是「用一次、加到**施用的那一格**土壤」，不是分摊全田。
   18 格农田要整体 +8 粪肥，就得用 18 坨粪便。
2. **上限 100**：每格每类养分钳制在 0~100（`farming_manager.lua:396`）；
   新锄开的格子初始随机 **20~40**（`STARTING_NUTRIENTS_MIN/MAX`）。
   所以一块地吃不满无限肥料——多施的浪费。
3. **新版作物不能直接喂**：`ACTIONS.FERTILIZE`（actions.lua:1806-1836）里能被
   喂的是旧式农田/作物/枯萎植物；新农场的作物没有施肥分支——
   肥料只能点在**裸露的耕地格**上。作物缺养分时不会自己从土里"回血"，
   缺口在下一阶段盘点照样记压力。

多次使用的容器型肥料（每次都给完整数值）：

| 物品 | 每次养分 | 次数 | 一件合计 |
| --- | --- | --- | --- |
| 化肥袋（fertilizer） | 粪肥 16 | **10**（`FERTILIZER_USES`） | 160 粪肥 |
| 催长剂瓶·发酵版 | 催长剂 32 | **5**（`SOILAMENDER_FERMENTED_USES`） | 160 催长剂 |

Wurt 技能树点出 `wurt_mosquito_craft_3` 后，蚊子血袋额外 +8/+8/+8（每格）。

**「粪便桶」（Bucket-o-Poop）联机版没有** —— 全脚本搜索 0 命中，
那是单机哈姆雷特 DLC 的物品。联机版里"能装多次的肥料"就是上面两件。

换算口径：面板第二页「肥料库存」输入的是**养分点数**，
物品 → 点数 = 物品值 × 个数（化肥袋算 16×剩余次数）。
例：配平器报「需补 96 粪肥」→ 12 坨粪便 / 6 只蝙蝠粪 / 1 袋化肥还剩 4 次富余。

对配比设计的指导意义：

1. **配平的真正价值是"少用催长剂"** —— 三组配平后一分肥料都不用施；
   一旦失衡，先想补的是便宜的堆肥/粪肥，催长剂省着用。
2. **8 点档作物要掂量**：洋葱/石榴/大蒜/辣椒/火龙果每阶段吃 8 点，
   如果吃的恰好是催长剂（洋葱/石榴），失衡时补起来最肉疼。
3. 万能补给（格罗姆粘液、堆肥包裹）留着救急，比单项肥料贵。

面板第一页配比下面那两行「缺啥补啥」就是这段的浓缩版。

同理，任何「一个消耗催长剂 + 一个消耗堆肥 + 一个消耗粪肥、且消耗点数相等」
的组合都成立，例如 `南瓜 : 芦笋 : 茄子 = 1 : 1 : 1`。

把 14 种作物的净变化都列出来就是（`−` 是吃掉，`+` 是吐出来）：

| 作物 | 催长剂 | 堆肥 | 粪肥 | | 作物 | 催长剂 | 堆肥 | 粪肥 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 胡萝卜 | −4 | +2 | +2 | | 玉米 | +2 | −4 | +2 |
| 南瓜 | −4 | +2 | +2 | | 芦笋 | +2 | −4 | +2 |
| 洋葱 | −8 | +4 | +4 | | 大蒜 | +4 | −8 | +4 |
| 石榴 | −8 | +4 | +4 | | 榴莲 | +4 | −8 | +4 |
| 土豆 | +2 | +2 | −4 | | 番茄 | −2 | −2 | +4 |
| 茄子 | +2 | +2 | −4 | | 西瓜 | +4 | −2 | −2 |
| 火龙果 | +4 | +4 | −8 | | | | | |
| 辣椒 | +4 | +4 | −8 | | | | | |

每一行三项相加都是 0 —— 这就是「只换种类、不增不减」的证据。

配平时看的是**点数**，不是株数：高消耗档的作物是 8 点，
所以一株 8 点的要配两株 4 点的、或者对应地把另外两组也堆到 8 点。

番茄（−2 −2 +4）和西瓜（+4 −2 −2）是**混合消耗型**：它们同时吃两种养分，
净变化的方向不是单一的。上面那张表里它们的数字也在，但做配比建议时
面板会把它们排除掉 —— 否则「几株」这个问题就没有唯一答案了。

### 前提：别在已经见底的地上直接种

上面所有的「收支归零」都有一个前提 —— **土壤里三项养分都还得有存量**。

原因在这一行（`components/farming_manager.lua:414`）：

```lua
local consumptioncount = math.min(nutrients[n_type], count)
```

消耗量被**钳到当前存量**。要扣 4 点、土里只剩 2 点，那就只扣 2 点。而随后
「归还」用的正是这个**实际**扣掉的量（`total_restore_count`），所以归还也跟着
从 `+2 +2` 缩成 `+1 +1`。

两件事同时发生：

| 后果 | 说明 |
| --- | --- |
| 总量仍然守恒 | 扣多少还多少，循环不会崩，只是整体规模自我缩小 |
| **作物会吃压力点** | `depleted` 的返回值直接进「养分压力」的判定 |

第二条才是要紧的。链条：

```lua
-- components/farming_manager.lua:417
depleted = depleted or consumptioncount ~= count

-- prefabs/farm_plants.lua:214  —— 返回值直接作为养分压力的判定结果
return TheWorld.components.farming_manager:CycleNutrientsAtPoint(x, y, z,
    inst.plant_def.nutrient_consumption, inst.plant_def.nutrient_restoration, not apply)

-- prefabs/farm_plants.lua:246
inst.components.farmplantstress:SetStressed("nutrients", NutrientsStressTest(inst, nil, true))
```

压力点攒够就长不成巨大作物、收获也会掉。所以：

- **配比解决的是「长期不让某一项见底」，不是「把已经见底的地救回来」**
- 新开的地不用管 —— 三项初始各 20~40，够启动
- 复用的地要注意 —— 被上一茬单一种植榨干过某项的，**先补一次肥再种**

这条也正好对上中文社区玩出来的经验：「间种的养分循环是需要初始动力的……
如果地块中一丝催长剂和堆肥都没有，那 A 就无法产出让 B 生长的堆肥，
B 也就没有办法循环出 A 所需要的催长剂。」——和上面那行 `math.min` 是同一件事。

## 压力点与巨大作物（v1.9.0 补的）

面板上的配比只管**养分**这一项。想种出**巨大作物**，还要看别的条件 ——
游戏里统一叫「压力点」，几个维度各算一份，**每个生长阶段盘点一次并累加**。

### 六类压力源

| 来源 | 判定 | 常量 / 代码 |
| --- | --- | --- |
| **家族** | 半径 4 内同种作物少于 4 株 | `FARM_PLANT_SAME_FAMILY_MIN = 4`、`_RADIUS = 4` |
| **季节** | 当前季节不在这个作物的 `good_seasons` 里 | `SeasonStressTest` |
| **拥挤** | 同一块地皮上超过 10 株作物 | `FARM_PANT_OVERCROWDING_MAX_PLANTS = 10` |
| **有害植物** | 半径 6 内有杂草 / 腐烂物 | `FARM_PLANT_KILLJOY_RADIUS = 6`、`_TOLERANCE = 0` |
| **缺水** | 土壤湿度低于这个作物的容忍值 | `FARM_PLANT_DROUGHT_TOLERANCE` |
| **养分** | 该阶段扣养分时存量不够（被 `math.min` 削过） | 见上一节 |

判定都在 `prefabs/farm_plants.lua:173-217`，由 `MakeStressCheckpoint` 汇总。

### 巨大作物的条件

`components/farmplantstress.lua:72-77`：

```lua
self.final_stress_state = stress <= 1 and FARM_PLANT_STRESS.NONE   -- allow one mistake
    or stress <= 6 and FARM_PLANT_STRESS.LOW
    or stress <= 11 and FARM_PLANT_STRESS.MODERATE
    or FARM_PLANT_STRESS.HIGH
```

**累计压力 ≤ 1 就算 NONE**（注释写着 *allow one mistake*）—— 全程最多错一次。
所以「某个阶段偶尔缺了一次水」还能救回来，但**持续性的问题一定毁掉巨大作物**。

### 这才说清「家族不足」为什么那么要命

家族不是「差一株少收一点」，而是**每个生长阶段都重新判定、每次都 +1 点压力**。
一株作物从种下到成熟大约盘点 4 次，那就是累计 4 点 —— 早就越过 1 点了。

所以面板第二页的诊断行按**每株的几何位置**报账：哪几株凑齐了邻居（能巨大）、
哪几株没凑齐（出普通作物），而不是只报一个总数。

## 种子从哪儿来（v2.2.3 源码核过）

**① 收获农作物的掉落，按最终压力分档**（`farm_plants.lua:344-362`）：

| 全程累计压力 | 收获 |
| --- | --- |
| 0 ~ 1 | **1 个超大作物物品**（巨大本体，见下） |
| 2 ~ 6 | 1 产品 + **2 个同种种子** |
| 7 ~ 11 | 1 产品 + 1 种子 |
| 12+ | 1 产品，没种子 |

**② 超大作物物品不是直接吃**（`veggies.lua:231-234`）：拿工具砍碎，
掉 `产品 ×2 + 同种种子 ×2 + 第 5 格（75% 产品 / 25% 种子）`
≈ **2.75 产品 + 2.25 种子**。也可以涂蜡保存、上战利品秤称重；烂掉变 4 个腐烂物。

**③ 喂鸟笼 = 稳定复制种子**（`birdcage.lua:106-152`）：

- 喂作物（有对应种子的）→ **1 个该作物的专属种子**；喂肉 → 1 个鸟蛋
- 喂普通种子 / 没对应种子的食物 → 1/3 概率小蝙蝠粪

**④ 两种种子**：专属种子（如土豆种子）种下去**必定**长成该作物；
普通种子野捡、20% 长杂草、其余随机出作物（比如胡萝卜 13.2%）。

**标准循环**：普通种子随便种 → 收获产品 → 喂鸟换专属种子 → 专精种植。
巨大作物是这条链的顶端：砸开 ≈ 2.25 个专属种子，收获本身又是 3 倍产量。

**★ 薇克巴顿的《应用园林学》**：读一次能把半径 30 内最多 10 株植物
自动催到成熟（升级版 15 株，还会顺手照料 + 补回土壤养分）。
**但被书催过的作物被打上 `no_oversized` 标记（farm_plants.lua:596），
收获判定（:518）一票否决 —— 压力再低也出不了巨大。**
书是"求快"工具：急着拿食物/种子才用；种巨大就别碰它。

### 杂草是唯一会打破配比平衡的东西

`weed_plants.lua:43`：

```lua
TheWorld.components.farming_manager:CycleNutrientsAtPoint(x, y, z, inst.weed_def.nutrient_consumption, nil)
--                                                                                        ↑ restore 传的是 nil
```

`restore = nil` 就是**只吃不还**。而 `weed_defs.lua:56-59` 里四种杂草的消耗都是
**三种养分各 2 点**（`FARM_PLANT_CONSUME_NUTRIENT_LOW`）。

**地里长草会同时掏空三项养分，而配比表是按「有借有还」算的** ——
所以面板底部专门加了一行提醒：看到草先拔掉。

### 顺带：季节也影响生长速度

`farm_plants.lua:367`：

```lua
return GetRandomMinMax(grow_time[1], grow_time[2]) * (is_good_season and 0.5 or 1)
```

**适宜季节生长时间减半（快一倍）**，非适宜季节照常。
再加上非适宜季节本身就是一个压力源 —— 所以「在适宜季节种」是一石二鸟，
这也是「本季配比」只列当前季节作物的原因。

### 配比里同类作物可以互换

算法只按「**吃哪一种养分、吃多少**」分组（`BuildSeasonPlan`），
所以同类作物完全等价：

- 吃催长剂：胡萝卜 / 南瓜（4 点）、洋葱 / 石榴（8 点）
- 吃堆肥：玉米 / 芦笋（4 点）、大蒜 / 榴莲（8 点）
- 吃粪肥：土豆 / 茄子（4 点）、火龙果 / 辣椒（8 点）

**没胡萝卜就用南瓜，没玉米就用芦笋** —— 效果一模一样。
面板上「本季配比」旁边现在也标了这句话。

## 和已有的耕种 mod 比

这块地不是没人碰过。「显示农场信息」方向上的 mod 有一批，但**「该种什么、怎么配平」这个角度基本是空的**。

|  | 它们 | 农事手册 |
| --- | --- | --- |

两个实际影响最大的点：

- **服务端 mod 你进不了别人的房间就没用。** garden detritus 和 Farm Plant Needs

**FarmCalc 的强项**：给的是**格位布局图**，直接告诉你哪种作物放哪个格子、还要满足
家族要求（同种作物相邻），比只说「几株」直观得多。这是下一步最值得借鉴的设计。

**它的已知问题**（都来自工坊评论区和作者自己的回复，非确证）：2021 年 7 月后停更；
作者承认「只考虑 1 个地皮的营养互补」；有用户报告装了三合一/棱镜那类大型内容包后
存档起不来，怀疑是它不兼容 mod 作物；界面缺本地化。

另外，Klei 论坛上有人手工试过**六边形布局**的 1:1:1 组合

## 数据是从哪来的

取自游戏本体，不是凭印象写的：

```
data/databundles/scripts.zip
  → scripts/prefabs/farm_plant_defs.lua     ← 作物数据（养分消耗、适宜季节）
```

   ```
   D:\UserData\Documents\Klei\DoNotStarveTogether\client_log.txt
   ```
   （这台机器的「文档」目录被改到了 D 盘，所以 Klei 目录也在 D 盘，
   **不在** `C:\Users\Administrator\Documents` 下面。）
   搜索 `FarmHelper`。正常加载会有三行：
   ```

   [FarmHelper] modmain 加载完成，快捷键 keycode = 104
   ```

   把报错那几行发我。

   | 日志里的现象 | 说明 |
   | --- | --- |
   | 缺 `环境自检通过` | 第 0 节那句 `setmetatable` 没生效，全局名全是 nil |

   必须在标题栏上重新按一次。
5. **位置不对 / 想恢复默认** → 右键点标题栏。或者在
   `D:\UserData\Documents\Klei\DoNotStarveTogether\` 下面搜 `farmhelper_pos`，

## 记一个坑：modmain 不在全局环境里

1.3.0 那一版一进游戏就崩。崩溃日志（`client_log.txt`）里长这样：

```
[string "scripts/widgets/widget.lua"]:421: calling 'SetHAnchor' on bad self (number expected, got nil)
LUA ERROR stack traceback:
  scripts/widgets/widget.lua:421 in (method) SetHAnchor (Lua) <420-422>
  ../mods/FarmHelper/modmain.lua:351 in (field) _ctor (Lua) <341-418>
  scripts/class.lua:191 in (upvalue) FarmHelperPanel (Lua) <181-194>
  ../mods/FarmHelper/modmain.lua:646 in (upvalue) postfn (Lua) <645-647>
  scripts/modutil.lua:157 in (upvalue) constructor (Lua) <155-158>
  scripts/screens/playerhud.lua:923 in (upvalue) OldSetMainCharacter (Lua) <915-949>
```

日志里还把出事时的局部变量整个 dump 出来了，**最关键的一行是**：

```
   name = FarmHelperPanel
   anchor = nil            ← 就是它
```

**原因不是锚点写法错了，是 `ANCHOR_LEFT` 在 modmain 里根本取不到值。**

modmain **不跑在 `_G` 里**。`mods.lua` 的 `CreateEnvironment()`（`mods.lua:302-331`）
会给每个 mod 现搭一张白名单表，里面只有：

```
pairs  ipairs  print  math  table  string  type  tostring  require
Class  TUNING  GLOBAL  modname  MODROOT
LEVELCATEGORY  GROUND  WORLD_TILES  LOCKS  KEYS  LEVELTYPE
```

再加上 `modutil.InsertPostInitFunctions()` 按 mod 名绑好后塞进去的那批接口
（`GetModConfigData`、`AddPrefabPostInit`、`AddClassPostConstruct`…）。

**这张表没有 `__index` 兜底** —— 查不到的名字直接就是 `nil`，
不报「未定义」，而是安静地变空值，然后在别处炸掉或者干脆不生效。
`util.lua:786` 的 `RunInEnvironment(fn, fnenv)` 确认就是 `setfenv(fn, fnenv)`。

裸写会拿到 `nil` 的常见名字：

| 名字 | 实际来自 |
| --- | --- |
| `ANCHOR_LEFT` / `ANCHOR_TOP` / `ANCHOR_MIDDLE` … | `constants.lua` |
| `MOUSEBUTTON_LEFT` / `MOUSEBUTTON_RIGHT` | `constants.lua` |
| `KEY_A` … `KEY_Z` | `constants.lua` |
| `TALKINGFONT` | `fonts.lua` |
| `TheSim` / `TheInput` / `TheWorld` | 引擎 |
| `STRINGS` | `strings.lua` |
| `tonumber` / `rawget` / `setmetatable` | Lua 基础库 |

**解法**是 `modmain.lua` 里最前面那一行：

```lua
GLOBAL.setmetatable(env, { __index = function(_, key) return GLOBAL.rawget(GLOBAL, key) end })
```

因为 `env` 自己的键优先级更高，`GetModConfigData` 这类**不在 `_G` 里、由 modutil
绑进 env** 的接口不受影响 —— 反过来，它也**不能**改写成 `GLOBAL.GetModConfigData`
（那个形式要靠 `modname` 参数，在 modmain 里拿不到）。

每个 mod 拿到的是各自独立的 env 表，所以这行不会干扰别的 mod。

加载日志里那行 `[FarmHelper] 环境自检通过` 就是在盯这件事；要是它变成
「环境自检失败，全局表里没有：…」，说明上面那句没生效。

## 记一个坑：面板挂在 controls 上，就得去 controls 找

1.3.2 那版按快捷键**完全没反应**，但日志里干干净净：

```
[FarmHelper] 环境自检通过
[FarmHelper] modmain 加载完成，快捷键 keycode = 104
```

**没有报错，也没有面板。** 原因是我自己写错了取面板的路径：

```lua
-- 挂的时候：挂在 controls 上
-- （AddClassPostConstruct 里的 self 就是 controls 这个 widget 自己）
AddClassPostConstruct("widgets/controls", function(self, owner)
    self.farmhelper_panel = self:AddChild(FarmHelperPanel(owner))
end)

-- 取的时候：却跑去 HUD 上找 —— 这段是错的
local hud = player.HUD
if hud == nil or hud.farmhelper_panel == nil then return end   -- 永远 nil，静默 return
```

`controls` 是 HUD 的**子节点**，不是 HUD 本身。挂载点在 `playerhud.lua:923`：

```lua
self.controls = self.root:AddChild(Controls(self.owner))
```

所以正确路径是 **`player.HUD.controls.farmhelper_panel`**。游戏自己的代码也都是这么摸的
（`mapscreen.lua` 的 `self.owner.HUD.controls.hover`、`woodie.lua` 的
`inst.HUD.controls.status`、`statusdisplays.lua` 的 `owner.HUD.controls.status`…）。

**教训**：`AddClassPostConstruct("widgets/xxx", function(self, ...))` 里的 `self`
就是**那个 widget 自己**。给它加的字段，之后必须经过同一个对象才能取到 ——
不能想当然以为它会挂到上一层去。而且这种错误**不报错**，只是安静地什么都不做，
所以更要紧的是**让代码开口说话**：现在面板挂上时会打一行
`[FarmHelper] 面板已挂到 HUD controls 上`，取不到面板时也会打一行警告，
下次一眼就能看出卡在哪一步。

### 续：主菜单里也有一份 controls

修好路径之后重启，面板终于挂上了，但**一启动就崩在主菜单**：

```
[string "scripts/widgets/widget.lua"]:349: attempt to call method 'GetWorldScale' (a nil value)
LUA ERROR stack traceback:
  scripts/widgets/widget.lua:349 in (method) GetWorldScale (Lua) <348-350>
  ../mods/FarmHelper/modmain.lua:535 in (method) UIScale (Lua) <534-542>
  ../mods/FarmHelper/modmain.lua:548 in (method) ScreenOrigin (Lua) <547-561>
```

**DST 主菜单为了角色预览也会构造一次 `controls`**，我们的 postinit 在那上面同样挂了面板。
而那份 UI 环境是不完整的 —— `widget.lua:349` 是：

```lua
return Vector3(self.inst.UITransform:GetWorldScale())
```

在那个上下文里 `UITransform` 上的 `GetWorldScale` 不存在，直接抛错。

（顺带解释了为什么 1.3.2 没崩：那一次主菜单的 controls 是在 modmain 加载**之前**
建好的，postinit 没赶上，面板只在游戏内创建。**这属于时序问题，不能指望它。**）

两处修掉：

1. **不在世界里就什么都不做**。`OnUpdate` 开头 `if TheWorld == nil then ... return end`，
   顺手把面板收起来 —— 免得设了「自动展开」的用户在主菜单看到它飘在角色预览上。
2. **取值链全面兜底**。`UIScale()` 里用 `pcall` 包住 `GetWorldScale`，
   `ScreenOrigin()` 里用 `pcall` 包住 `GetWorldPosition`。这两个内部都是
   `inst.UITransform:xxx()`，环境不完整时同样会抛错；拿不到就按 1、按本地坐标算。

**教训**：一个纯显示面板，绝不能因为拿不到 UI 数值把游戏带崩。
凡是 `inst.UITransform:xxx()` 这类「过渡期可能不可用」的调用，一律 `pcall` + 兜底。

## 图标是怎么取到的（v1.4.0 已实现）

**不用自己画图、不用装 Mod Tools** —— 游戏物品图集里本来就有每种作物和种子的图。

游戏自己就带一个「植物登记表」界面，里面每种作物都有图标。它的画法
（`scripts/widgets/redux/farmplantpage.lua`）可以直接抄：

```lua
local img_name = item_name .. ".tex"                  -- 例如 "carrot.tex"
local img_atlas = GetInventoryItemAtlas(img_name, true)  -- 返回 atlas 路径
local icon = root:AddChild(Image(img_atlas, img_name))
icon:ScaleToSize(28, 28)
```

关键在这个 `GetInventoryItemAtlas`（定义在 `scripts/simutil.lua`）：它会在游戏的
`images/inventoryimages1.xml` ~ `4.xml` 里搜这个名字，返回包含它的图集路径。
**所以图标是现成的，直接从游戏资源里取，mod 里不用带任何贴图。**

要取的名字：

| 用途 | 图标名 | 依据 |
| --- | --- | --- |
| 作物 | `carrot.tex` | 收获到的作物物品的贴图 |
| 种子 | `carrot_seeds.tex` | 背包里种子物品的贴图 |

两个坑（代码里都处理了）：

1. `GetInventoryItemAtlas` 找不到时返回 `nil`，**必须给兜底** —— 因为紧接着就是
   `Image(atlas, tex)`，参数不对**能把游戏直接带崩**。本 mod 的做法是
   **取不到就干脆不画这个图标**（不退到 `missing.tex`，少一个图比冒崩的风险划算），
   并且只在第一次失败时打一行日志，不刷屏。
2. **洋葱和番茄的作物图标名必须换** —— 这条是把 14 种作物逐个比对出来的，不是猜的。
   `GetInventoryItemAtlas` **只搜 `inventoryimages1~4.xml` 这四个**
   （`simutil.lua:670-680` 的实现，**不搜** `inventoryimages.xml`）。核对结果：

   | | 作物图标 | 种子图标 |
   | --- | --- | --- |
   | 其余 12 种 | 都在 1~4 里 ✓ | 都在 1~4 里 ✓ |
   | **洋葱** | `onion.tex` **不在** ✗ → 用 `quagmire_onion.tex`（在 3 里） | `onion_seeds.tex` ✓ |
   | **番茄** | `tomato.tex` **不在** ✗ → 用 `quagmire_tomato.tex`（在 3 里） | `tomato_seeds.tex` ✓ |

   所以代码里有一张 `ICON_REMAP` 表专门做这个替换。
   **不换的话这两行的作物图标会直接空着**（取不到就不画，是退化而不是崩）。

**v1.4.0 的排版参数**（都在这几个常量里）：

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `PANEL_W` / `PANEL_H` | 650 × 680 | 比初版的 520×486 大了一圈 |
| `ROW_H` | 26 | 行高，为的是塞下 22px 图标 |
| `ICON` | 22 | 图标边长 |
| `COL` | 表 | 列坐标，含 `icon1` / `icon2` 两个图标位 |
| 字号 | 14~22 | 初版是 12~18，整体放大约 1/4 |

## 更远的方向

- **给出格位布局图**（最值得做的一条）：现在面板输出的是「洋葱 1 株 : 大蒜 1 株 :
  火龙果 1 株」，但真正下地时的问题是「**哪个格子放哪个**」。FarmCalc 就是靠
  这个拿到 35 万订阅的。做法是把「几株」转成一张 N×N 网格图，同时把**家族要求**
  一起算进去（同种作物相邻 3 株以上，否则照样吃压力点，判定在
  `farm_plants.lua` 的 `FamilyStressTest`）。种 9 格的话大概是：

  ```
  洋葱 大蒜 火龙果        ← 三种各 3 株，竖着分三列
  洋葱 大蒜 火龙果
  洋葱 大蒜 火龙果
  ```

- **实时显示脚下土壤的三种养分数值**：游戏有 `TheWorld.components.farming_manager:GetTileNutrients(x, y)`，
  但这是服务端数据，要显示在客户端得走 netvar 同步，比现在这个纯客户端面板复杂一档。
- **标出背包里现有的种子**：直接把你手上有的种子对应的行高亮出来，
  那样连名字都不用认了 —— 和加图标是同一个目的的两种做法。
- **只显示当前季节能种的作物**：在 `RefreshRows()` 里按 `crop.seasons[season]` 过滤一行就行。
- **给面板加折叠分组**：现在 14 行全展开，做成三组可折叠会更清爽。
- **记住面板是否展开**：现在每次进游戏都按 modinfo 里的「自动展开」来，
  可以跟位置一样持久化，做到上次收起下次就还是收起的。
- **把面板尺寸也记进设置**：现在 `PANEL_W` / `PANEL_H` 是改代码，
  可以挪到 modinfo 里做成「大 / 中 / 小」三档。
